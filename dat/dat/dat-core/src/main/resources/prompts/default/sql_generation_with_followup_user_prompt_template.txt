**Anti-pitfalls (these cause silent zero-row results or parse errors — read carefully):**
- Window functions MUST be `DENSE_RANK() OVER (ORDER BY ...) AS rn` (or ROW_NUMBER). Missing `OVER(...)` is a parse error.
- **CRITICAL — `rn` cannot appear in the same WHERE as the DENSE_RANK that produced it.** MySQL evaluates WHERE before window functions, so `SELECT ..., DENSE_RANK() OVER(...) AS rn FROM t WHERE rn <= N` raises "Unknown column 'rn' in where clause". You MUST put DENSE_RANK in a CTE (or subquery), then filter `rn <= N` in the OUTER SELECT that reads from it.
- **Recommended shape — exactly 2 CTEs:**
  - CTE 1 (e.g. `dd`): `SELECT index_number, MAX(data_dt) AS data_dt FROM <t> WHERE index_number IN (...) AND curr_code = '...' AND index_value IS NOT NULL GROUP BY index_number`. Group by **index_number ONLY** — RANKING compares all orgs at the same snapshot date, not at each org's own latest date.
  - CTE 2 (e.g. `ranked_orgs`): join the table back to `dd` on `(index_number, data_dt)`, apply the level + blacklist filters from constraint #5, then compute `DENSE_RANK() OVER (ORDER BY t.index_value <ASC|DESC>) AS rn`.
  - Outer `SELECT ... FROM ranked_orgs WHERE rn <= N` (or `rn = N` for 第N名).
- Do NOT partition the window by `org_code` — `DENSE_RANK() OVER (PARTITION BY org_code ORDER BY ...)` produces a per-org local rank, not a cross-org ranking. No PARTITION BY for RANKING.
- All filters (`curr_code`, `index_number`, REGEXP level, NOT IN blacklist, date) MUST be inside the CTE that feeds the ranking. Do NOT put them only in the outer WHERE.
- Do NOT add `index_number`, `standard_name`, `brchna`, `business_meaning` to the outer WHERE — the CTE already filters by index_number.

{% if index_context.orgAggregationMode == 'SUBTRACT' %}
**SUBTRACT: org A minus org B.** The first org in `queryOrgCodes` is the minuend, the second is the subtrahend.
{% if index_context.resolvedOrgNames %}User mentioned: {% for n in index_context.resolvedOrgNames %}`{{ n }}`{% if not loop.last %} vs {% endif %}{% endfor %}.{% endif %}

Use this skeleton. Replace every `<...>` placeholder with the corresponding value from constraints #1–#4. Keep the CTE names, column names, and structure exactly as shown — only substitute the placeholders and add date filters if constraint #4 requires them:
```sql
WITH latest_data AS (
  SELECT index_number, org_code, MAX(data_dt) AS data_dt
  FROM <table>
  WHERE index_number IN ('<index_number>') AND curr_code = '<currency>'
    AND org_code IN ('<A>', '<B>') AND index_value IS NOT NULL
  GROUP BY index_number, org_code
),
org_values AS (
  SELECT t.index_number, t.org_code, t.data_dt, t.index_value,
         t.standard_name, t.mea_unit, t.index_data_sources_id
  FROM <table> t
  INNER JOIN latest_data ld
    ON t.index_number = ld.index_number AND t.org_code = ld.org_code
    AND t.data_dt = ld.data_dt AND t.curr_code = '<currency>'
  WHERE t.index_number IN ('<index_number>') AND t.org_code IN ('<A>', '<B>')
),
diff_calc AS (
  SELECT
    MAX(data_dt) AS data_dt,
    MAX(standard_name) AS standard_name,
    MAX(mea_unit) AS mea_unit,
    MAX(index_data_sources_id) AS index_data_sources_id,
    COALESCE(SUM(CASE WHEN org_code = '<A>' THEN index_value ELSE 0 END), 0)
    - COALESCE(SUM(CASE WHEN org_code = '<B>' THEN index_value ELSE 0 END), 0) AS diff_value
  FROM org_values
)
SELECT data_dt, standard_name, mea_unit, index_data_sources_id, diff_value
FROM diff_calc;
```
- `<A>` = first org in constraint #2 `queryOrgCodes` (minuend). `<B>` = second org (subtrahend).
- If constraint #4 has a date filter (EQ/IN/BETWEEN), add it inside BOTH `latest_data` AND `org_values`.
- Do NOT add `org_code` or `brchna` to `diff_calc` — adding them makes the aggregation per-org and `diff_value` becomes NULL.
- `COALESCE(SUM(CASE ...), 0)` is mandatory around each arm — without it, a missing org row produces NULL for the whole diff.

{% elif index_context.orgAggregationMode == 'DIVIDE' %}
**DIVIDE: org A / org B ratio.** The first org in `queryOrgCodes` is the numerator, the second is the denominator.
{% if index_context.resolvedOrgNames %}User mentioned: {% for n in index_context.resolvedOrgNames %}`{{ n }}`{% if not loop.last %} ÷ {% endif %}{% endfor %}.{% endif %}

Same skeleton as SUBTRACT, only `diff_calc` becomes `ratio_calc`:
```sql
ratio_calc AS (
  SELECT
    MAX(data_dt) AS data_dt,
    MAX(standard_name) AS standard_name,
    MAX(index_data_sources_id) AS index_data_sources_id,
    ROUND(
      COALESCE(SUM(CASE WHEN org_code = '<A>' THEN index_value ELSE 0 END), 0) * 100.0
      / NULLIF(COALESCE(SUM(CASE WHEN org_code = '<B>' THEN index_value ELSE 0 END), 0), 0)
    , 2) AS ratio_value
  FROM org_values
)
SELECT data_dt, standard_name, '%' AS mea_unit, index_data_sources_id, ratio_value
FROM ratio_calc;
```
- `NULLIF(denominator, 0)` is mandatory — prevents division-by-zero.
- Output `mea_unit` is always `'%'` (dimensionless ratio).

```sql
WITH latest_data AS (

    AND t.data_dt = ld.data_dt AND t.curr_code = '<currency>'
  WHERE t.index_number IN ('<index_number>') AND t.org_code IN (<org_list>)
),
sum_calc AS (
  SELECT
    MAX(data_dt) AS data_dt,
    MAX(standard_name) AS standard_name,
    MAX(mea_unit) AS mea_unit,

SELECT data_dt, standard_name, mea_unit, index_data_sources_id, sum_value
FROM sum_calc;
```
- `<org_list>` = all org codes from constraint #2, each quoted, comma-separated (e.g. `'00001', '00002'`).
